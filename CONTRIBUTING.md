# Contributing to AI API Atlas

Thanks for improving the directory.

## Source of truth

`data/providers.json` is the source of truth. `README.md` is generated by `scripts/generate_readme.py`; please do not hand-edit the generated sections.

## What belongs here

A provider should expose a real developer API and have a currently usable $0 access path. Login-required free tiers are explicitly welcome. Tell us exactly what the user must do:

- create an account;
- create an API key/token;
- add a payment method, if any;
- complete identity verification, if any;
- use a specific free model or endpoint, if the free access is model-specific.

## What does not belong here

Do not submit expired programs, discontinued products, “first $5 free” promotions that are not recurring, or web-chat products with no developer API.

A provider may still be listed as `free_trial_key` or `monthly_credit` when the provider currently grants that access to free accounts. The directory labels those cases so readers can distinguish them from a permanent/recurring free tier.

## Evidence standard

Every new entry needs at least one primary provider source supporting the free-access claim and one technical/API source when those are separate. Model names and quotas should be copied from the current provider docs or model catalog.

Never add an API key, token, password, or secret to a pull request.

## Local checks

```bash
python scripts/validate_data.py
python scripts/generate_readme.py
python scripts/check_links.py
python scripts/fetch_openrouter_free.py
```

## Pull requests

Keep provider additions focused. If a provider has a dynamic model catalog, add the stable provider record and use a generated file or script for the changing model list.

## OmniRoute-integrated upstreams

When adding an upstream that is usable through OmniRoute, include `access_via: ["OmniRoute"]`, state whether the endpoint is a direct API or an integration reference, and cite both the upstream documentation and the relevant OmniRoute provider documentation. Do not describe an OmniRoute integration as a standalone provider quota unless the upstream source supports that claim.
